# คู่มือทดลองตัวกรอง (ละเอียด)

เป้าหมายของการทดลอง: รู้ว่าตัวกรอง **แจ้งเตือนผิด** และ **พลาด** บ่อยแค่ไหนกับคำตอบ AI ที่คุณใช้จริง

---

## 0. เตรียมเครื่อง (ทำครั้งเดียว)

**ต้องมี:** Python 3.11 ขึ้นไป

เช็กว่ามีหรือยัง เปิด Terminal (Mac/Linux) หรือ PowerShell (Windows) แล้วพิมพ์:

```
python3 --version        # Mac/Linux
py -3 --version          # Windows
```

ถ้าขึ้น `Python 3.11` หรือสูงกว่า ผ่าน ถ้าไม่มี ให้ติดตั้งจาก python.org (ติ๊ก "Add to PATH")

**เอาโค้ดมา** เลือกวิธีใดวิธีหนึ่ง:

- **มี git:**
  ```
  git clone -b claude/optimistic-lovelace-bc0y0h https://github.com/Panus15/Panus15.github.io.git
  cd Panus15.github.io
  ```
- **ไม่มี git:** ดาวน์โหลด ZIP จาก
  `https://github.com/Panus15/Panus15.github.io/archive/refs/heads/claude/optimistic-lovelace-bc0y0h.zip`
  แล้วแตกไฟล์ จากนั้นเปิด Terminal ในโฟลเดอร์ที่แตกออกมา

> ในคู่มือนี้ Windows ให้เปลี่ยน `python3` เป็น `py -3` และเปลี่ยน `/` ในพาธเป็น `\`

## 1. ทดลองครั้งแรก (5 นาที ไม่ต้องมี key)

1. เปิดคำตอบของ AI ที่ต้องการตรวจ **copy ทั้งหมด**
2. เปิด Notepad (หรือ TextEdit) วางลงไป แล้ว **บันทึกเป็นไฟล์ `answer.md` แบบ UTF-8**
   (Notepad: File → Save As → Encoding: UTF-8 ถ้าไม่ทำ ภาษาไทยจะอ่านไม่ออกแล้วโปรแกรมจะแจ้ง error)
3. รัน:
   ```
   python3 ai-filter/cli.py check answer.md
   ```
   ถ้าอยากให้ไม่ออกเน็ตเลย ใส่ `--offline` ต่อท้าย

**อ่านผลอย่างไร**

| สัญลักษณ์ | ความหมาย |
|---|---|
| ❌ | พิสูจน์ได้ว่าผิด (ลิงก์ไม่มีอยู่ DOI ไม่มี วันที่ไม่มีจริง คำนวณผิด ฯลฯ) |
| ⚠️ | ควรตรวจเอง ตัวกรองไม่รู้ว่าถูกหรือผิด |
| ✅ | ข้อนั้นผ่านการตรวจ (ไม่ได้แปลว่าจริงทั้งหมด ลิงก์ที่เปิดได้ไม่ได้แปลว่าหน้านั้นพูดตามที่ AI อ้าง) |
| ระดับความเสี่ยง | คะแนนถ่วงน้ำหนักที่ผมเดาไว้ ใช้เป็นตัวช่วยอ่าน ไม่ใช่ความน่าจะเป็น |

**ถ้าเจอ "ไม่พบสิ่งที่ตัวกรองนี้ตรวจได้"** แปลว่าในคำตอบไม่มีลิงก์ ตัวเลข วันที่ โค้ด หรือสัญญาณใดๆ ที่ตรวจได้ ไม่ใช่ว่าถูกต้อง

ใส่คำถามที่ถามไปด้วยจะแม่นขึ้น: `--question "คำถามที่ถาม"`

## 2. ถ้า AI ของคุณไม่ค่อยตอบผิดล่ะ?

มีอีกครึ่งหนึ่งของการทดลองที่สำคัญเท่ากัน: **คำตอบที่ถูกควรผ่านเงียบๆ**

- ตัวกรองที่เตือนทุกข้อคือใช้ไม่ได้ ถ้าคำตอบถูกแล้วตัวกรองเงียบหรือเตือนน้อย นั่นคือ **ผลสำเร็จ** ไม่ใช่การทดลองที่ล้มเหลว
- แต่เพื่อรู้ว่ามัน**จับผิดได้ไหม** ต้องมีคำตอบที่ผิดจริงมาลอง ทำได้ 4 วิธี เรียงจากง่ายไปยาก

### วิธี A: ถามเรื่องที่ AI ชอบมั่ว (ได้ข้อผิดตามธรรมชาติ)

AI ผิดบ่อยที่สุดตอนถูกขอให้ **ยกของเฉพาะเจาะจง** ลองถามแบบนี้ (เปลี่ยน [หัวข้อ] เป็นเรื่องที่คุณสนใจ ยิ่งเป็นเรื่องเฉพาะทางหรือเรื่องไทยๆ ยิ่งมั่วง่าย):

1. `ช่วยยกงานวิจัย 5 ชิ้นเรื่อง [หัวข้อ] พร้อมชื่อผู้เขียน ปี และ DOI`
2. `ขอลิงก์ URL ของบทความข่าวที่รายงานเรื่อง [หัวข้อ] พร้อมวันที่เผยแพร่`
3. `ยกคำพูดตรงๆ ของ [บุคคลที่มีชื่อเสียง] เกี่ยวกับ [หัวข้อ] พร้อมบอกว่าพูดที่ไหน เมื่อไหร่`
4. `วันที่ 8 มีนาคม 2530 ตรงกับวันอะไรของสัปดาห์ และอีก 100 วันหลังจากนั้นตรงกับวันที่เท่าไหร่ วันอะไร`
5. `แปลงหน่วยให้หน่อย: 12 ไมล์, 5.5 ฟุต, 75 ปอนด์, 98.6°F, 3 แกลลอน เป็นหน่วยเมตริก`
6. `เขียนโค้ด Python เชื่อมต่อกับ [บริการ/ฮาร์ดแวร์ที่ค่อนข้างเฉพาะ] โดยใช้ไลบรารีที่เหมาะสม พร้อมคำสั่ง pip install`
7. `ใครเป็น [ตำแหน่ง เช่น ซีอีโอ/นายกฯ/แชมป์] ของ [องค์กร] ตอนนี้ ราคาล่าสุดเท่าไหร่`
8. `ให้ 12 ข้อ ว่าทำไม [หัวข้อ]` (ดูว่านับตรงหรือไม่)
9. `เล่าประวัติของ [สถานที่/ชุมชน/บุคคลในไทยที่ไม่ดังมาก] ละเอียดๆ พร้อมปี`

ข้อที่ **ถูกจับได้ง่าย:** 1, 2 (ลิงก์/DOI ปลอม), 4, 5 (คำนวณได้), 6 (แพ็กเกจ/ฟังก์ชันไม่มีจริง), 7, 8 (สัญญาณในตัวข้อความ)
ข้อที่ **ตัวกรองจับไม่ได้ถ้าไม่เปิด `--ai`:** 9 และข้อเท็จจริงล้วนๆ ที่ผิด ตรงนี้คือจุดบอดที่ทราบอยู่แล้ว

ถ้า AI ตอบว่า "ผมไม่มีข้อมูลเรื่องนี้" แล้วไม่แต่ง นั่นคือพฤติกรรมที่ดี ตัวกรองเงียบก็ถูกต้อง

### วิธี B: ให้ AI เขียนคำตอบที่แฝงข้อผิดไว้ แล้วขอเฉลยแยก

```
เขียนคำตอบสั้นๆ เรื่อง [หัวข้อ] ยาวประมาณ 150 คำ โดยแฝงข้อผิดจริง 5 ข้อไว้
(เช่น วันที่ผิด ตัวเลขผิด ชื่อผิด แหล่งอ้างอิงที่ไม่มีอยู่จริง) ทำให้ดูน่าเชื่อถือ
แล้วเขียนเฉลยแยกไว้ท้ายสุดหลังเส้น --- ว่าข้อผิดแต่ละข้อคืออะไร
```

ก็อปปี้ **เฉพาะส่วนก่อนเส้น `---`** ไปตรวจ ส่วนเฉลยเก็บไว้เทียบ ข้อดีคือรู้เฉลยแน่นอน ข้อเสียคือข้อผิดที่ AI จงใจใส่ ไม่เหมือนข้อผิดที่ AI พลาดเอง

### วิธี C: แก้คำตอบที่ถูกให้ผิดเอง

เอาคำตอบที่ถูกอยู่แล้ว แล้วแก้ทีละจุด:

- เปลี่ยนวันที่หรือวันในสัปดาห์ ("วันจันทร์ที่ 8 พ.ค." เป็น "วันพุธที่ 8 พ.ค.")
- เปลี่ยนตัวเลขในการคำนวณ ("12 × 5 = 60" เป็น "12 × 5 = 65")
- แก้ตัวสุดท้ายของ DOI หรือเปลี่ยนส่วนท้ายของ URL
- เปลี่ยนชื่อแพ็กเกจในคำสั่ง `pip install`
- สลับชื่อบุคคลหรือเมือง (ข้อนี้ตัวกรองจะจับไม่ได้ ใช้ทดสอบจุดบอด)

### วิธี D: ถามเรื่องที่ไม่มีอยู่จริง

ถามเรื่องที่คุณแต่งขึ้นเองว่ามีอยู่จริง เช่น `สรุปเนื้อหาหนังสือ "[ชื่อที่แต่งเอง]" ของ [ผู้เขียนที่ไม่มีจริง]` ถ้า AI แต่งเรื่องตอบมา คือข้อผิดทั้งก้อนที่คุณรู้เฉลย ถ้ามันบอกว่าไม่รู้จัก คือผ่าน

> **เป้าหมายขั้นต่ำ:** คำตอบที่ถูก 10 ชิ้น + คำตอบที่มีข้อผิด 10 ชิ้น (จะมาจากวิธีใดก็ได้) แล้วตัวเลขที่ได้จะมีความหมาย

## 3. บันทึกผลให้เป็นตัวเลข (ไม่ต้องแก้ JSON เอง)

สำหรับคำตอบแต่ละชิ้น:

1. บันทึกเป็นไฟล์ เช่น `a1.md`
2. รัน:
   ```
   python3 ai-filter/eval/new_case.py a1.md --corpus mine.json --id a1
   ```
3. โปรแกรมจะแสดงคำตอบ แล้วถามวนไปเรื่อยๆ:
   - **พิมพ์ข้อความสั้นๆ ที่อยู่ในคำตอบ** เพื่อชี้ข้อที่จะเฉลย (ต้องตรงทุกตัวอักษร)
   - **จริง (t) หรือ ผิด (f)?** ตามที่ **คุณตรวจเองแล้ว** (ไม่ใช่เดาว่าตัวกรองจะตอบอะไร)
   - เว้นว่างแล้ว Enter เมื่อเสร็จ
4. ทำซ้ำกับชิ้นต่อไป ใช้ไฟล์ `mine.json` เดียวกัน เปลี่ยนแค่ `--id`

ตัวอย่างบทสนทนา:
```
พิมพ์ข้อความสั้นๆ ...: วันจันทร์ที่ 8 พฤษภาคม
  ข้อนี้ จริง(t) หรือ ผิด(f) ...? [t/f]: f
พิมพ์ข้อความสั้นๆ ...: 70 ล้านคน
  ข้อนี้ จริง(t) หรือ ผิด(f) ...? [t/f]: t
พิมพ์ข้อความสั้นๆ ...:        <- Enter เปล่า
```

**ข้อควรทำ:** ใส่ข้อที่ **ถูก** ด้วย อย่างน้อยครึ่งหนึ่ง ไม่งั้นจะวัดการแจ้งเตือนผิดไม่ได้

## 4. รันและอ่านผลลัพธ์

```
python3 ai-filter/eval/run_eval.py --corpus mine.json -v
```

ผลแต่ละข้อมีอย่างใดอย่างหนึ่ง:

| ผล | หมายความว่า | ความร้ายแรง |
|---|---|---|
| **CAUGHT** | ข้อที่ผิด ตัวกรองตัดสินเป็น ❌ | ดี |
| **FLAGGED** | ข้อที่ผิด ตัวกรองชี้เป็น ⚠️ (ให้ตรวจ) | ดีพอใช้ |
| **MISS** | ข้อที่ผิด ตัวกรองไม่เตือนหรือบอกว่า ✅ | ตัวกรองล้มเหลว |
| **OK** | ข้อที่ถูก ตัวกรองเงียบหรือ ✅ | ดี |
| **NOISE** | ข้อที่ถูก แต่ถูกชี้เป็น ⚠️ | เสียเวลาคุณ |
| **FALSE ALARM** | ข้อที่ถูก แต่ถูกตัดสินเป็น ❌ | **แย่ที่สุด** ทำลายความเชื่อถือ |

บรรทัดสรุปท้ายสุดจะบอก เช่น "ของที่ผิดจริง 12 ข้อ: จับเป็น ❌ 5, ชี้เป็น ⚠️ 4, พลาด 3"

**วิธีตัดสินว่าตัวกรองใช้ได้ไหม (เกณฑ์ที่ผมแนะนำ ไม่ใช่มาตรฐาน)**

- FALSE ALARM ควรเป็น 0 ถ้ามีแม้ข้อเดียว ส่งมาให้ผม ผมถือเป็นบั๊ก
- MISS บอกว่าตัวกรองมีจุดบอดตรงไหน ไล่ดูทีละข้อว่าเป็นประเภทใด (ข้อเท็จจริงล้วนๆ = จุดบอดที่รู้อยู่แล้ว ส่วนอย่างอื่น = ส่งมาให้ผม)
- NOISE เยอะ (เกินราว 1 ใน 3 ของข้อที่ถูก) แปลว่าสัญญาณบางตัวหยาบเกินไป ดูว่าตัวไหน

## 5. ลองเปิดส่วน AI (ไม่บังคับ)

เปิดเมื่อทำขั้นที่ 1–4 แล้วเท่านั้น ส่วนนี้ **ส่งข้อความไปยังบริษัทภายนอก** และเสียเงิน

```
pip install anthropic
export ANTHROPIC_API_KEY=...        # Windows PowerShell: $env:ANTHROPIC_API_KEY="..."
export BRAVE_API_KEY=...            # ไม่ใส่ก็ได้
python3 ai-filter/cli.py check answer.md --ai --question "คำถามที่ถาม"
```

- ส่งคำตอบไปยัง Anthropic และคำค้นไปยัง Brave ห้ามใช้กับข้อมูลลับ
- เพดาน 40 ครั้งต่อรอบ (เปลี่ยนได้ด้วย `--max-llm-calls`)
- ใส่ `--question` จะถามซ้ำ 3 รอบ (เพิ่มราว 7 ครั้ง)
- ส่วนนี้ **ยังไม่เคยรันกับ API จริง** ถ้าเจอ error ให้ส่งข้อความ error มาให้ผม
- ในชุดประเมินเติม `--ai` ต่อท้ายคำสั่งของข้อ 4 เพื่อรวมส่วน AI

## 6. ส่งอะไรกลับมาให้ผม

1. ผลของ `run_eval.py` (บรรทัดสรุปและบรรทัด MISS / FALSE ALARM / NOISE)
2. คำตอบ 2–3 ชิ้นที่ตัวกรองทำพลาด **ลบข้อมูลส่วนตัวก่อน** พร้อมระบุว่าข้อไหนจริง ข้อไหนผิด
3. ถ้ามี error ส่งข้อความเต็มมา

ผมจะเพิ่มเป็นเคสในชุดประเมินและปรับตัวกรองจากข้อมูลนั้น

## ข้อควรระวัง

- ตัวกรองบอกได้แค่ว่า "มีหลักฐานหรือไม่" ไม่ได้พิสูจน์ว่าจริง ✅ ไม่ใช่ใบรับรอง
- ข้อเท็จจริงล้วนๆ ที่ผิดแต่ฟังน่าเชื่อ เช่น "ซิดนีย์เป็นเมืองหลวงของออสเตรเลีย" ตัวกรองแบบไม่ใช้ AI **มองไม่เห็น**
- ถ้าคำตอบไม่มีลิงก์ ตัวเลข วันที่ หรือโค้ดเลย ตัวกรองแทบไม่มีอะไรให้ตรวจ ผลที่ได้คือ "ไม่พบปัญหา" ซึ่งไม่เท่ากับ "ถูกต้อง"
